# Golden Multi-Turn Transcripts Test Suite

This directory contains data-driven scenario files for verifying end-to-end patient conversations across all 4 supported languages (`en`, `hi`, `hi-Latn`, `or`) for 8 core journeys.

## Directory Structure

Each scenario file is named `<journey>.<lang>.json`:
- **Journeys (8):**
  - `faq_fees`: Consultation fee inquiry answered with seeded facts.
  - `book_confirm`: Booking journey from intent to slot selection to explicit button confirmation.
  - `book_choose_again`: Booking journey where patient rejects slot confirmation and requests re-selection.
  - `status`: Booking status inquiry for an existing appointment.
  - `cancel_confirm`: Cancellation journey with explicit button confirmation leading to cancellation.
  - `cancel_keep`: Cancellation journey where patient chooses to keep the appointment unchanged.
  - `medical_refusal`: Safety gate refusal for medical/clinical questions, triggering staff escalation alert.
  - `unsupported_media`: Handling of unsupported media (e.g. voice/audio notes) prompting for text.
- **Languages (4):**
  - `en`: English
  - `hi`: Hindi (Devanagari script)
  - `hi-Latn`: Hinglish (Latin-script Hindi)
  - `or`: Odia (Odia script)

Total: 8 journeys × 4 languages = 32 scenario files.

## Scenario JSON Schema

```json
{
  "lang": "hi",
  "tenant": {
    "name": "Apex Clinic",
    "locale_default": "hi"
  },
  "setup": {
    "seed_booking": true
  },
  "steps": [
    {
      "send": {
        "text": "अपॉइंटमेंट बुक करना है कल"
      },
      "expect": [
        {
          "kind": "list",
          "button_key": "ui.choose_time",
          "body_key": "booking.picker_prompt",
          "min_rows": 1
        }
      ]
    },
    {
      "send": {
        "tap": "slot:first"
      },
      "expect": [
        {
          "kind": "buttons",
          "ids": ["booking:confirm", "booking:cancel"],
          "body_key": "booking.confirm_prompt"
        }
      ]
    },
    {
      "send": {
        "tap": "booking:confirm"
      },
      "expect": [
        {
          "kind": "text",
          "key": "booking.booked"
        }
      ]
    }
  ],
  "final": {
    "bookings_confirmed": 1,
    "bookings_cancelled": 0,
    "conversation_state": "bot",
    "open_escalations": 0
  }
}
```

### Fields

- `lang` (required): Target language code (`en`, `hi`, `hi-Latn`, `or`).
- `tenant` (optional): Tenant metadata override (`name`, `locale_default`).
- `setup` (optional): Pre-test setup conditions:
  - `seed_booking`: Pre-seeds an existing confirmed booking and contact for the patient.
- `steps` (required): Sequence of conversation turns:
  - `send`: Inbound message payload:
    - `text`: Plain text string.
    - `tap`: Button or list tap. Supports `"slot:first"` / `"slot:last"` (dynamically resolved against the last outbound list message) or explicit button IDs (`"booking:confirm"`, `"cancel:confirm"`, etc.).
    - `media`: Media message type (e.g. `"audio"`).
  - `expect`: Outbound messages generated by the step in order:
    - `kind`: `"text" | "list" | "buttons" | "template" | "none"`.
    - `key` / `body_key` / `button_key`: i18n string key or template key whose language-specific template is compiled to regex (`{param}` -> `.+?`) and matched against actual outbound content.
    - `contains`: Required substring inside message body.
    - `ids`: List of button reply IDs that must match.
    - `min_rows`: Minimum number of interactive list rows.
    - `name`: Template name (e.g. `"escalation_alert_staff"`).
- `final` (optional): End-of-journey assertions against the database:
  - `bookings_confirmed`: Count of confirmed bookings.
  - `bookings_cancelled`: Count of cancelled bookings.
  - `conversation_state`: State of the conversation (`"bot"` or `"human"`).
  - `open_escalations`: Count of open escalation records.

## Global Assertions

Every outbound message captured by the recorder is subject to global assertions:
1. **No leaked internal tags:** Outbound content must never contain `[source_ref`.
2. **De-hardcoded identity:** Clinic names must match the scenario tenant name and never `Sharma`.
3. **No raw datetimes:** Outbound text must never contain raw unrendered ISO-8601 datetimes (`\d{4}-\d{2}-\d{2}T`).
4. **WhatsApp limits:**
   - Button titles must be ≤ 20 characters.
   - List button labels must be ≤ 20 characters.
   - Section titles and row titles must be ≤ 24 characters.
5. **Localization fidelity:** Non-English flow messages must match their localized templates without English fallback bleed.
